## 实际派发与加权账

先纠正数量：c64-wave2模块导出12个整块变体及2个C256 attention变体，共14个。当前生产只有8个被调用；C256四个整块变体全是0次，C256的FFN/QKV实际在multihead-fast-padded-wave-packed模块。不要把它们算作热点。

从0.35真实一帧的214次派发记录kernel、window、threads、block。自然循环用汇编CFG的支配关系识别，避免把冷分支回跳误判成循环；FFN qt4×hidden4（每次2个hidden tile）、mix qt4、attention qt4、projection qt4，attention float尾部另有ci2；PDL轮询只计一次，等待次数不等于等待时长。WMMA数量与源码公式独立核对：整块每wave `168+4.5*C`，C256 attention每wave232。

**计数口径是循环加权的控制流上界**：未把post=0/3/4和边缘谓词按实际lane掩码逐条模拟，SALU/VALU/VMEM的互斥尾部分支可能重复计入；WMMA核心数严格核对。相邻段的指令可被调度，分段是debug callsite归属，投影WMMA按实际循环纠正。它用于定位可删指令，不能代替下面的实测时间账。debug模块与正常基线的代码/常量/metadata段相同，ledger.py锁定归档generated source的SHA。

DGX假gfx1201重新导出fswin64/128/256、fswinds三条、fswinfusedup三条。aco-compare.json记录静态opcode分类与ISA SHA。无backedge的fswin核心：

|---|---:|---:|
| C64 | 2199 / 416 | 5573 / 456 |
| C128 | 2220 / 704 | 5844 / 744 |
| C256整块 | 2245 / 1280 | 5800 / 1320（生产不用） |

ACO C64按token分两个wave，HIP按头；C128/C256的NR_HWAVES=1与HIP头划分更接近。HIP额外24次对角残差WMMA和16次固定分母WMMA解释40次差额；不能把这些当编译器浪费。ACO激活/归一化/分母有不同数学路线，含本项目已关的packed-half/成对FP8解包，不照抄。fswinds/fusedup还融合pool/上采样，其整体总数不和我们的纯block直接相减。

## 候选

- **B / W2_BYTE_INPUT_LOADS**：FP8输入八字节读取，去掉逐字节float往返；残差输入也整组读再按原顺序解码。标量256编码探针确认只有0x7f→0xff例外，word内无跨字节进位的整数掩码保留这一规范化，正负零不变。
- **R / W2_RTZ_PAIR**：一次pkrtz转换两个不同输入，保持每个half位；只改contract与FFN残差RTZ。原LDS两plane已经是FP8、8字节读写，不能照搬C32的half LDS布局。新组织另让LLVM把残差读取合并得更宽。
- **T / W2_FULL_WINDOW**：投影尾部分完整/边缘两路。内部免逐像素判断，边缘原样。代码增大、收益不稳定，不采用。
- **C / W2_DIRECT_COORDS**：直接算tile的x/y，去掉“坐标→扁平p→除/取余还原坐标”。workw是8的倍数且支持几何无32位溢出；五种几何×三族×四shift的2,256,192个坐标/边界判断全部相同。
- **D / W2_DIRECT_FEATURE**：C256 attention直接读取原feature，省去LDS plane0；LDS32→16KiB，byteout VGPR169→144。但不形成稳定整网收益，不采用。

输出的byte路径本来已经直接Pack8；float路径要交给Down/Up，不能删除decode。不存在C32第一刀那种尚未处理的输出FP8往返。

本轮没有扩展MODE范围。审计发现既有整块核的24对MODE写之间为空（QKV FP8转换被LLVM移出），与前轮C32遇到的情况相似；本轮保持其数值路径，未借此改饱和语义。所有候选审计均无f16收窄混入MODE区间；历史范围census只作为既有实现背景，不充当新段证明。
