# C64 融合核手改汇编（2026-09-27）

目的：试一次"拿 LLVM 编出的 ISA 当底稿、手工改热点、再汇编回 .hsaco"，弄清可行性、收益上限和维护成本。底稿 = P 配方
（生产配方 + `W2_PACK8 4`，分段 FP16_OVFL）的 `c64-wave2`，gfx1201。实验文件在 `Development/HIP/experiments/c64-hand-asm/`。

## 1. 工具链：汇编往返可行

- `asm_compile.cpp`（新，mingw 交叉编译）：用驱动自带 `amd_comgr_3.dll` 做 ASSEMBLE_SOURCE_TO_RELOCATABLE(8) →
  LINK_RELOCATABLE_TO_EXECUTABLE(7)，输入就是 `rtc_compile` 顺手吐出的 `.hsaco.s`。不要 SDK、不要 GPU。
- 7.8 MB 的整模块 `.s`（29 个模块里的 c64-wave2，含 C64/C128/C256 全部变体）原样汇编：一次成功，节大小、地址全同。
  字节差只有两类：16 位操作数字面量的高半（`0xffffffef` 回写成 `0x0000ffef`，硬件只读低 16 位）和 rsrc1 的 SGPR 粒度字段
  （gfx10+ 忽略）。7 用例 12 帧逐位一致。**结论：`.s` 是可以直接改、直接编回生产模块的。**

## 2. 热点在哪（c64_wave2_bi_bo，C64 链中段）

按循环次数加权，一个窗口动态 VALU(+VOPD) ≈ 5650 条：FFN 隐层循环（×16）1856、FFN 第二段（×4）1524、
注意力直线段 843、序言 527。FFN 隐层循环每半轮：8 个 clamp(±4) → 多项式 → `x*poly` → 8 个 `x+0`（−0→+0）→
2 个 `v_mov v38/v39, 0` → 4 条 `cvt_pk_fp8`。

## 3. 手改（h1）与一个关键坑

- **坑：`+0` 不能删。** 激活多项式 `poly = g*(0.447265625 − 0.055908203125|g|) + 0.89453125` 在 clamp 端点 g=−4 处
  **恰好等于 +0**，于是所有 x ≤ −4 的 `x*poly` 都是 −0，打包成 0x80 而不是 0x00。编译器留着那条 add 是对的。
- **能做的：`x*c` 和 `+0` 合成一条 `fma(x,c,+0)`。** 精确积加精确 0 再舍入一次 = 乘法的舍入；和永远不是 −0。
  用 `v_dual_fmaak_f32 …, 0x0` 成对发射（VOPD 约束：目标寄存器奇偶不同、两个 src0/vsrc1 分属不同 bank，按现有寄存器分配
  正好都满足）。
- **`v_mov v38/v39, 0` 是死的**：两半 16 位都会被 `cvt_pk` 写满。另做了硬件探针（`zsign.hip`）：fp8 WMMA 在
  C=+0 或 C=−0、乘积全是 −0、±1 精确抵消等情形下输出**一律 +0**，从不出 −0。
- 结果：该循环每轮少 12 条 VALU（每窗口约 192 条，约 3.4%），7 用例逐位；**ABBA 测不出来**（900 9.606→9.615、
  1080 13.357→13.359 ms，噪声内）。只改了一个核的一个循环，占整网太小。
- 冒险处理：改动范围内的 `s_delay_alu` 直接删（只是发射提示）；VALU 写 v38/v39 与前一条 WMMA 读它们之间保持和编译器
  一样的 ≥2 条 VALU 间隔；MODE 开关位置不动。

## 4. 回推到源码（Q = `W2_PACK8 6`）：真正的收获

手改看清了病根：LLVM **不会**把 `mul` 和 `add 0` 收缩成 fma——把 `+0` 挪到 `s_setreg` 段外、和乘法紧挨着也不收缩
（add-0 条数 186→191，fma 不变）。于是在源码里显式写：`W2_Q8_SETF(A,e,x,y)` = `__builtin_fmaf(x,y,0.f)`，用在四个"乘积
再打包"的站点（FFN 激活 `a*poly`、QKV 归一化 `q*inv`、`query*qinv`、softmax `exp*inv`），其余打包值在存入时 `+0`。

- 12 个 wave2 变体（C64/C128/C256 × bi/bo）每个少 165～195 条指令（约 −4%），主要是 VOPD 对被 fma 对取代。
- 7 用例 12 帧逐位；默认配方（W2_PACK8 3）重编与 M 模块代码段相同（非 6 时 `SETF` 就是原来的 `SET(x*y)`）。
- 两批 ABBA（槽 0/3 = P，1/2 = Q，各 1000 帧）：900 −0.013 / −0.028 ms，1080 −0.015 / −0.025 ms，约 −0.2%。

## 5. 经验

1. **汇编往返零成本可用**：COMGR 自带汇编器，`.s` 可以直接编回生产模块，逐位验证照旧。以后"想看某个写法编成什么"
   或"手工验证一个 ISA 猜想"，不必绕源码。
2. **手改最大的价值是当显微镜，不是当产品**：这次手改本身测不出收益，但它逼着把每条指令的语义想清楚——
   找到了 `+0` 的真实用途（g=−4 处多项式为 +0）、确认了 WMMA 不出 −0、看清 LLVM 不做 `mul+add0` 收缩——
   然后一条源码改动覆盖了全部 12 个变体。
3. **LLVM 本来就对的地方**：寄存器分配已经尽量凑 VOPD（奇偶 bank 限制下凑不满是约束不是懒）；`+0` 不能删；
   WMMA 前后的等待与间隔很紧，没找到可省的 `s_wait`。
4. **维护成本**：手改是对某一版 `.s` 的补丁（按指令序列匹配），源码一改就得重做；两个架构、每个开关组合各一份。
   只适合"验证猜想"，不适合常驻生产。推广到 C32 的意义同上：先用手改找病根，再回源码修。
5. 收益量级校准：一个核里一段循环省 3% VALU，整网 < 0.1%。要测得出来，改动得覆盖多个核或多个族。
