# 09-30 用 mochizuki 公开的 NVIDIA 原版输出量我们的画质（只量，未改生产）

源：github.com/mochizuki0323/DLSSNR-AMD @ d1185d2（0.0.2.5），`docs/ngx-verification`。NVIDIA 侧 = RTX 5090 + Wine 跑原版 `nvngx_dlssnr.dll` 310.8，NGX 公共 API，每帧 Reset。

## 1. 口径

- **他公开了什么**：单帧三档（1080/1440/4K）的输入 PNG、NVIDIA 输出 PNG、他自己的输出 PNG。**运动序列只公开了数字**（`moving-sequence-results.json`），没有输入、没有 NVIDIA 输出（文档原话：合成序列不出图），生成脚本也不在仓库 → **运动序列无法同口径复测**，本轮只做单帧。
- **指标**（`psnr.py`）：8-bit RGB，全部像素×三通道 MSE，峰值 255；SSIM 三通道平均，11×11 高斯 σ1.5。
- **复算校验**：用他发布的 PNG 复算 他 vs NVIDIA = **45.56 / 47.99 / 49.06 dB**，输入 vs NVIDIA = 26.44 / 27.72 / 28.69，与他公布值**逐位一致**；SSIM 0.99605/0.99679/0.99697（他 0.99607/0.99678/0.99697，窗口实现差 ±2e-5）。管线口径对齐。
- **我们的输入/输出**：PNG 8-bit → v/255 存 RGBA16F（f16 舍入 <2⁻¹²，他那边 NVIDIA 读 UNORM）；`DLSS5_CODEC_SRGB=1`（输入视为已编码的网络工作面，直通；解码线性化合成后再编码——与他 UNORM 直通路径在同尺寸下都退化为"输出≈网络输出"）；输出 round(clamp·255)。seed 0、单帧 Reset、零运动、`STRENGTH=1,1`、`OUTPUT_SMOOTH` 关。
- **runner**：`bench_ngx.cpp` = `Development/HIP/benchmark_live_capture.cpp` 仅把固定 1296×720 改成读 `BENCH_W/BENCH_H`；走完整 NativeGameFrame（编码→网络→解码）。9070 上 `run.ps1`，模块 `build.ps1`。

## 2. 关键发现：我们网络里写死的是 Style=1

预处理块 16 个特征里的控制常量（`prefix_fast.hip`、`c32_fused_ffn_attention.hip`、`wave_owned_c32.inc`）是 `{…,1,.0078125,1,…,1,1,…,1,0}`；对照 mochizuki `nr_graph.cpp`（`s434 = style/128`，tone/structure/skin/other 均 1），**0.0078125 = Style 1/128，即 Style=1**，其余与他默认一致。他和 NVIDIA 这次都跑 **Style=0**。
- 发布模块原样（Style1）对 NVIDIA(Style0)：**24.06 dB**，比不处理的输入（26.44）还远——不是误差，是风格不同。
- 测量用：只把该常量改 0（三个源文件、四处），其它源码与 HEAD 相同，重编 31 模块（`mods-hips`）。先验证未改动的 HEAD 重编（`mods-hipb`）输出与现装剑星模块**逐位相同**（sha ae7e3118…），所以改 0 版与发布版只差这一个常量。

## 3. 结果（单帧，Style0 测量版，对 NVIDIA）

| 档 | 配置 | PSNR | SSIM | 均差 (1/255 RGB) | 全通道≤1 步 |
|---|---|---:|---:|---|---:|
| 1080p | mochizuki 0.0.2.5 | 45.56 | 0.9961 | +0.36 +0.44 +0.38 | 67.5% |
| 1080p | a) 发布配方 跳 42/43/46 EXACT | **44.26** | 0.9956 | +0.15 +0.23 −0.02 | 62.6% |
| 1080p | b) 全 71 块 EXACT | **47.43** | 0.9963 | −0.02 +0.05 +0.09 | 76.9% |
| 1080p | c) AE（跳块 / 不跳，第 8 帧） | 44.26 / 47.43 | — | 与 EXACT 逐位相同 | — |
| 1440p | a) 跳块（产品路径：缩到 1080 档网络） | 35.70 | 0.9853 | | 9.2% |
| 1440p | b) 全块 | 35.94 | 0.9859 | | 10.4% |
| 4K | a) 跳块（同上） | 33.05 | 0.9799 | | 7.5% |
| 4K | b) 全块 | 33.29 | 0.9808 | | 8.3% |
| 1080p | 发布模块原样（Style1） | 24.06 | 0.9237 | +2.68 +1.76 +0.36 | 0.3% |

- AE：单帧同一输入每帧 Reset，第 8 帧与 EXACT 哈希相同（76915ec5… / 29920953…），单帧口径下 AE 无差别，要看 AE 得有运动序列。
- 1440/4K：NVIDIA 在原生分辨率跑网络，我们的档位上限 1080（`FIT_LARGE` 双线性缩到 1920×1080 跑再贴回），33～36 dB 由**几何**主导，不代表数值精度；我们没有 1440/4K 档，无法同几何比。

## 4. 结论

- **口径对齐**：复算他的数与公布值完全一致。
- **1080p 同几何（1152 行）**：全 71 块 47.43 dB，**比 mochizuki 高 1.9 dB**，亮度偏移也小（他 +0.4/255，我们 <0.1）；我们对原 CUBIN 的 raw float RMSE≈0.008 落到 8-bit 就是这个量级。
- **跳 42/43/46 损失 3.17 dB**（47.43→44.26），并带来 +0.15/+0.23 的系统偏移，发布配方因此比 mochizuki 低 1.3 dB。**差距主要来自跳块**，float FMA/几何（1080 档下与 NVIDIA 同为 1152 行）/后处理不是主因。
- **更大的问题是风格**：发布网络写死 Style=1，用户在默认场景里看到的和 NVIDIA 默认(Style0) 差 20+ dB 量级，这不是精度，是参数；是否该跟 NVIDIA 默认、或做成开关，待 Zero 定（我们的 Style1 从哪个捕获来的需另查）。
- 未做：运动序列（无公开 NVIDIA 数据）；1440/4K 同几何（无档位）。
