# 重组 C512 块 / ViT 块：设计研究（2026-09-30 深夜，只设计，不写生产代码、未上 GPU）

**结论先行**：推荐先做 **方案 P——C512 跨块就绪队列**（把 swin-persistent 的 C256 队列机制搬到 C512：一段 8 块/5 块、每块 5 个现役核体作为 stage，一次队列派发跑完），逐位（核体与累加顺序不动，只改调度），900 预估 **−0.10～−0.25ms**，把握中。方案 A（块内 attention→project 就绪队列）是 P 的子集，可作 P 的第一步。方案 F（mix→ffn→proj 一核、hidden 留片上）和 V（ViT 八块全局栅栏持久化）收益低或与负账重叠，排后。

所有数字引自下列账本，本页没有新测量：
`hip-roofline-20260930`（C512 900 实测 1245µs / 现实理想 419µs，2.97 倍；ViT 829 / 316，2.63 倍；空隙 2.4µs/派发）、`fill-cu-20260930`（mix 单 WG 占全量 65%、attn-project 68%、ViT contract 65%、project 56%：延迟型）、`gap-fusion-20260930`（拼小核不赚；PDL 延伸到 C512 被 325W 吃回）、`swin-persistent-20260929`（C256 队列 900 −1.9%）、`swin-persistent-c128-c64-20260929`（C128/C64 队列不赚）、`deep-layers-20260929`（R/RF 单 wave 寄存器 FFN 慢）、`c512-ffn-lds-20260930`（Daniel ffwd 组织、LDS 共用权重不赚）、`kernel-map-900-20260930`（逐核 µs）。

## 0. 现状（900，0.38 之后）

C512 每块 5 派发 × 13 块 = 65（去 shift_pack 后）：

| 核 | 13 次合计 µs | 类型（fill-cu） |
|---|---:|---|
| c512_qkv_attention_compact（WG=窗口×头，448/560×64） | 602 | 吞吐型 22～31% |
| mh_attention_project_frag_c512（752×32） | 214（hoist 后约 −40） | **延迟型 68%** |
| split_mix_blocked_h16w_m32（376×32） | 209 | **延迟型 65%** |
| split_ffn_fused_fp8_t8（752×128） | 188 | 吞吐型 19% |
| split_projection_frag（752×32） | 127 | 吞吐型 21% |

依赖形状：mix/ffn/proj 都是 **token 局部**（同一批 token 的 512 通道进、512 通道出）；qkv_attention 按**窗口**取 token（半满窗口，900 50×30 补到 56×32）；attn-project 又是 token 局部但要**全部 16 个头**的 AV。块与块之间窗口有移位（shift），下一块的一个窗口依赖上一块至多 4 个窗口/片——与 C256 swin 队列同构。

ViT 每块 6 派发 × 8 块 + 2 gather = 50：qkv_w5 213、contract 197、expand 174、attention 117、project 72、pack 24（µs）。ViT 的 attention 是**全 400/640 token 全局**，依赖是整行，没有 tile 级放行。

## 1. 方案 P：C512 跨块就绪队列（推荐）

**数据流**：沿用 `swin-persistent.hsaco` 那套：CPU 预建依赖图，`init → run → recover` 三派发；任务 = (块, stage, tile)。tile 取**窗口对齐的 token 片**（一个 C512 窗口 = 64 token；900 每块 28/35 个窗口）。stage 与任务：
- S1 mix(tile)、S2 ffn(tile)、S3 proj(tile)：token 局部，只依赖同 tile 上一 stage；
- S4 qkv_attention(窗口, 头)：依赖本窗口所含 tile 的 S3（移位后至多 4 个上一块 tile）；
- S5 attn_project(tile)：依赖本 tile 所在窗口的 16 个 S4 头任务；下一块 S1 依赖 S5。
每个 stage 的函数体**逐字复制现役核体**（同 C256 做法：sp_run256 里七个 sp 函数与原型逐一同体），任务到核体只换"blockIdx → 任务坐标"映射。

**每 WG 工作量 / 资源**：WG 取各 stage 最大的 64 线程（2 wave；FFN t8 的 128 线程拆成 2 个任务或 WG 取 128、较小 stage 空一半——原型两种都编，看 VGPR）。VGPR = 各核体并集上界：qkv_attention 134、ffn 108、mix 102、proj 83、aproj 80 → 预计 **134～150**（C256 队列 154 无 spill）；LDS = max(6144, 5184, 4096) ≈ **6KB**。驻留：134 VGPR → 每 SIMD 约 10 wave，够。

**逐位**：能。每个输出元素的 K 顺序、F/Hrtz/q8 量化点、写出格式都不动；中间张量照样写 global（先不去掉，去掉是 F 方案的事）。只有调度顺序变，无跨 WG 归约，所以不改数值。验收沿用 19 组（7 用例 × EXACT/AE × 12 帧 + AE CSV + 900/1080 票号回绕）+ swin 那套故障注入/回绕压力。

**预估**：
- 派发 65 → 2 段 × 3 = 6（−59）。按空隙 2.4µs/派发上限 ≈ 0.14ms；
- 更大的一块是**延迟型核的串行链被别的 tile 掩住**：mix/aproj 单 WG 就占全量 65～68%，现在每块都要"等最慢的那条链走完才进下一核"，队列里 tile k 的 aproj 与 tile k+1 的 mix、别的窗口的 attention 重叠。C256 队列省 18 派发拿到 900 −0.16ms（≈9µs/派发，远大于 2.4µs 空隙），就是这部分；
- 保守：按 C256 每派发收益的 1/4～1/2 算，**900 −0.10～−0.25ms、1080 −0.08～−0.20ms**（C512 共 1245/1676µs，离现实理想 826/1148µs）。

**与负账对照**：
- *C128/C64 持久化不赚*：那两族每层已是 1～2 个融合核，每段只省 0～1 派发。C512 每块 5 派发、13 块，是 C256（6 层）之后派发最密的一段——与 C256 同类，不与 C128/C64 同类。
- *PDL 延伸 C512 被功耗墙吃回（pdl-c512）*：PDL 只填**派发空隙**，指令总量不变，省下的时间以降频还回。P 的主要收益来自**延迟型核的等待被重叠**（WG 在等读时 CU 空转也在耗电但不做功，重叠后同样的功耗做更多功），性质与 C256 队列相同——C256 队列在同一功耗墙下仍拿到 −1.9%。但这是**最大风险**，见下。
- *gap-fusion 拼小核不赚*：那是把两个核拼成一个带额外置换访存的核；P 不改访存形态。

**最大风险**：① 功耗墙：若 C512 的等待被填满后整卡时钟再降，收益可能像 pdl-c512 一样被吃掉一半以上；② 队列开销：每任务一次原子领票 + 依赖计数，C512 任务很碎（每块约 94 个 16-token tile 或 28～35 窗口 × 16 头），5 stage × 13 块 ≈ 5000 任务/帧，若每任务额外 ~0.3µs 串行化在 head 原子上会吃掉收益（C256 每段 624/893 任务）；③ VGPR 并集超过 ~160 使占用率掉档。

**最小验证实验**（止损明确）：
1. 只做 900 编码段（块 23～30，8 块 40 派发），`experiments/c512-persistent/`，从 swin-persistent 复制框架，stage 体从现装模块同源拷贝；宏默认 0、宿主开关默认 0，不改生产。
2. 先看资源：VGPR ≤ 160、private 0，否则调 WG 形状，两次不过即停。
3. 逐位：该段输出对现装 golden 168 帧逐位；不过即查映射，不改数学。
4. 计时：HIP 段 span（`DLSS5_HIP_SPAN_PROBE=1` 写进 flags 文件）+ 整网 ABBA 三轮。**止损**：900 三轮中位改善 < 0.03ms，或任一轮变慢 → 停并记负账（附时钟遥测看是否被功耗墙吃掉）。过了再加解码段（5 块）与 1080。

## 2. 方案 A：C512 块内 attention → project 就绪队列（P 的第一步/退路）

**数据流**：只把 S4 qkv_attention 与 S5 attn_project 合进一次派发：任务 = (窗口, 头) 做 attention，写 AV（现役格式）后给窗口计数 +1；第 16 个到达的头发布该窗口的 aproj tile 任务（4 个 16-token tile × 8 个 64 列块），由任意空闲 WG 领走。每块 1 派发代替 2（或 C512 13 块一次派发，只含这两 stage）。

**资源**：同 P 的 S4/S5 并集：134 VGPR、6KB LDS。**逐位**：能（同 P）。

**预估**：派发 −13（~0.03ms）+ aproj 的延迟链（单 WG 68%）与其他窗口 attention 重叠：aproj 900 约 175µs（hoist 后），能掩掉 1/3～1/2 → **900 −0.05～−0.10ms**。

**风险**：最后到达的头决定 aproj 放行时机，窗口间负载不均（半满窗口）可能让尾部更长；功耗墙同 P。
**最小实验**：jobbench 单块两核 vs 队列一核，同 fixture FNV 逐位，128 次图捕获 7 轮；单块不快 ≥1.5µs（≈13 块 0.02ms）即停。它比 P 小一周，但 P 若成立会把它包进去，所以只在 P 的队列开销太大时作为退路。

## 3. 方案 F：C512 mix → ffn_t8 → projection 一核，中间留片上（排第三）

**数据流**：WG = 一个 16-token 片 × 全 512 通道，8 wave，每 wave 64 列（与现役每 wave 64 列同形）；mix 输出按现役量化（F(Hrtz)）写进 LDS（16×512 字节或 half：8～16KB），ffn t8 读 LDS 算 hidden，hidden 的 FP8 写 LDS（16×H 字节），contract8 再进 LDS，最后 projection 读 LDS 出块输出；权重仍从 L2 读。900 94 个片 × 8 wave = 752 wave，与现役 proj 同量。

**资源**：VGPR ~110（各段串行，寄存器可复用）；LDS 8～16KB（mix 出）+ 16×H（hidden）+ 8KB（contract8）——H 需按实际宽度核算，若 H=2048 则 hidden 32KB，总 ≈ 50KB/WG，**每 CU 只驻 1 个 WG**，是硬风险。

**逐位**：能，前提是每个中间量量化点与现役逐一对上（写 LDS 与写 global 的是同一字节）；K 顺序不变。若为省 LDS 改用 Daniel 式"hidden 留寄存器、FP8 激活"，mix 入口 A 从 f32 变 FP8 → **有损，属 C 段待拍板**。

**预估**：派发 −26（0.06ms 空隙上限）+ 中间张量（mix 出/hidden/contract8，每块 3～4MB）不出 L2 → 本来就在 L2/MALL，DRAM 省不了多少；三核 524µs 对 Daniel 382µs，差距他那边主因是 FP8 数据形态（c512-ffn-lds 结论）。逐位版预估 **900 −0.03～−0.08ms**。

**与负账对照**：*R/RF（单 wave 寄存器 FFN / 前接 mix）慢 0.14～0.30ms*——败在每输出组 wave 从 4 减到 1、供数变差；F 保持 8 wave/片、每 wave 64 列的供数形态，差在这里。但 *LDS 共用权重不赚*（权重在 L2）说明 L2→CU 供数不是瓶颈，F 省下的"中间张量 L2 往返"同样是 L2 流量，兑现存疑。**把握低**。
**最小实验**：只合 ffn_t8 + projection 两段（hidden 已是 FP8，接口最简单）为单核，jobbench 逐位 + 计时；单核和不快 ≥2µs/块，或 LDS>32KB 占用掉到 1 WG/CU 即停。

## 4. 方案 V：ViT 八块全局栅栏持久化（排最后）

**数据流**：ViT 各 stage 依赖整行（全局 attention），无 tile 放行；只能用常驻 grid + 设备级栅栏（原子计数 + 轮询）把 8 块 × 6 stage 串成一次派发，每个 stage 之间一次全网栅栏。**逐位**：能（只改调度）。
**预估**：派发 −47，但每个设备级栅栏本身 ~1～3µs（原子 + 轮询 + 缓存写回），与派发空隙 2.4µs 同量级，**净 0～0.05ms**；ViT 的延迟型核（contract 65%、project 56%）在全局栅栏下无法与别的 stage 重叠，拿不到 P 的那份主要收益。
**与负账对照**：gather 折叠、pack 合并（V/P/G/Q/R 系列）都败在额外访存；V 不改访存但收益本身就小。ViT 真正的余差在 attention（38 vs 22～24µs，1080）和 QKV 精度（C 段 FP8），不在组织。**不建议现在做**。

## 5. 排序（收益 × 把握）

| 方案 | 900 预估 | 逐位 | 把握 | 成本 |
|---|---|---|---|---|
| **P C512 跨块队列** | −0.10～−0.25ms | 是 | 中（C256 同类已赚；功耗墙是变数） | 中：框架现成，stage 体照搬 |
| A 块内 attn→proj 队列 | −0.05～−0.10 | 是 | 中 | 小；P 的子集/退路 |
| F mix→ffn→proj 一核 | −0.03～−0.08（逐位版） | 是（FP8 激活版有损） | 低（R/RF、LDS 共用已负） | 中 |
| V ViT 全局栅栏 | 0～−0.05 | 是 | 低 | 中 |

**推荐先做 P 的 900 编码段原型**（§1 最小实验），止损线 900 三轮中位 < 0.03ms 或任一轮变慢。

## 本分析可能漏掉的

- 窗口/tile 映射、shift 依赖只按 C256 同构推断，C512 compact 窗口半满（448/560 两种 grid 交替）的实际依赖图需原型时从 host 代码核对。
- ffn_t8 的 hidden 宽度 H 没在本页核实（F 的 LDS 估算依赖它）。
- "延迟链被重叠"的收益没有计数器可证，唯一裁判是整网 ABBA。
