## 3. 剩下最大、能逐位追的 3 处
1. **C512 attention 投影（900 +11µs×13≈+143，1088 +15×13≈+199）**。我们 1 wave/WG、16 token×64 列，K 循环每 2 步等 load 到 0（ISA：8 次往返），残差 f32 读写；他 WN=4、e4m3 读写。类别：组织方式（流水深度/每 WG wave 数）+ 数据格式。负账：B8/`C512_PROJ_FB8`（字节残差，持平）、`C512_PROJ_M32`/最终投影 M32（反慢）、`C512_T8_NO_F32`（1080 一轮 +0.008 未收）、`C512_SPLIT_N`。
2. **ViT 1088 档 QKV + attention（1088 +16+13 ≈ +29µs/块×8 ≈ +230；900 只 +5/+3）**。token 多时我们 attention 640 与 QKV 掉得比他快——组织方式（tile/占用率随 token 数），非数值。负账：KSPLIT（有损档里也变慢）、4wave/64key 预取、QKV 块重排、V 请求组织（余项未拆清）。
3. **C32 中间块（≈+16µs/块×8 ≈ +135 两档）+ post（+43/+62）**。类别：数值取舍（Hrtz/softmax 逐位出口）+ 组织。负账：`CW_POST_FULL_TILE`、C32 权重缓存、CW_FAST_NUM（有损，不算）、复合量化 C32。

## 4. 对第 1 处的候选：`C512_PROJ_DEEP`（multihead-fast-padded-wave-packed，宏默认 0，双架构编过）
仿 `C512_COMPACT_QKV_DEEP`：K 的 32 个（k32,half）步全展开，D 深寄存器环，死行读 `first` 行再 select 置零，逐累加器顺序不变。
- d4（第一版环）：**19 组 SAME**；ABBA 三轮 900 +0.221/+0.245/+0.249，1080 +0.223/+0.225/+0.229ms，p99 7.421→7.659、10.123→10.337。**全慢，不收。**
- ISA 原因：VGPR 顶到 255，42～62 条 scratch 溢出。LLVM 把 B 片段 load 全部提前，并把 acc[0] 的 32 步串成一条链再做 acc[1..3]（加 sched_barrier、asm memory clobber、改成两组命名寄存器、照抄 QKV_DEEP 的基址+立即数写法，四种写法都溢出）。和 C512_FFN_PIPE 同型负账：这条核在 LLVM 下做不出手排流水。
- 宏 0 重编与现装该模块代码逐条相同（compare-modules identical）。**没装机，剑星/鬼武者/fast-tier exact 快照均未动。**

## 5. 续（光第二单）：WN4 重组 + ViT 1088 测清楚

### 5.1 `C512_PROJ_WN4`：attention 投影照他改成每 WG 4 wave
和 09-29 `C512_PROJ_M32` 的区别：M32 是两个 token tile 共用权重，**wave 数减半**、每 wave 的串行链从 64 条拉长到 128 条，在 token 少的 900 档直接变成时延。WN4 反过来：grid 不变，一个 128 线程 WG = 同样的 16 token × 64 列，**每个 wave 只管 16 列**（1 个累加器、32 条 WMMA），wave 数 ×4，串行链缩到 1/4；4 个 wave 读同一段 A（L0 共享），权重片段各读各的。初值、操作数、K 顺序、出口逐元素同 HOIST_RES 路径。
- 模块宏 `C512_PROJ_WN4`（默认 0，新导出 `mh_attention_project_frag_c512_wn4`）；宿主 `HIP_C512_PROJ_WN4`（默认 0，开了且模块有导出才走，threads=128）。w2 = 全展开（94 VGPR，无 scratch），w1 = unroll 4。
- w2：**19 组 SAME**；ABBA 900 +0.013/+0.011/−0.004，1080 +0.018/+0.006/−0.008ms，合并 p99 7.477→7.479、10.289→10.275。w1：900 +0.013/−0.007/−0.001，1080 +0.024/+0.033/+0.027。**持平偏慢，不收。**
- 结论：wave 数和串行链长都不是这条核的瓶颈（M32 减 wave 变慢、WN4 加 wave 也不变快），链内 ≈11µs/块 的差多半不在核本体的组织上；剩下的可能是 f32 残差读写和前后核的衔接。这条线停。

以 chain 为例，每块差 ≈ +16µs（900，事件地图 130.7 对他 116.6）拆成两段：
1. **单核本体 ≈ +10µs：数值取舍。** 单核 120.7 对他约 110。c32-aco 的指令账里 chain 普通向量 5079 条，其中激活与 hidden 打包 1632 条（clamp/NaN 规范化、分步乘加、FP8 clamp+转换），Q/K 归一化、score/exp、softmax 也是逐位保留的 Hrtz/RTZ 链；他用 `NR_ACT_F32`/`NR_NORM_F32`/e4m3 一次舍入。这部分不能逐位改。
2. **链内比单核多 ≈ +10～14µs：频率，不是组织方式。** 同一个核，单测 120.7、链内 130.7～134.2；整网在 325W 功耗墙下降频（单核测是高频，c128-c64 与 c512 两轮已用 DUP 证实同样现象）。VALU 越多越吃功耗，第 1 点的数值开销在链内被放大，不是独立的第二个病因。他的数本来就是链内测的，所以这一段不该当作"我们的组织多出来的空档"。
3. **组织方式能逐位追的只剩 up（块 66）4×4→8×8 分发**：16 条 `ds_bpermute`/qt，他用 LDS 存再读；估 ≤3µs、只有 1 块。mapped/finish 的输入/尾部各轮已收（CW_VEC_INPUT、CW_FINISH_FULL_TILE、tail-vec、c32-align、CW_HOIST_UP、CW_DIAG_ONLY）。

**结论**：C32 中间块的 +16µs/块 ≈ 10 数值 + 6 数值在功耗墙下的放大；组织方式上没有值得出刀的件（up 分发 ≤3µs）。和 tail-c32-gap 的判断一致，C32 剩余差距归 C 段（有损，需 Zero 拍板）。这轮没做候选。
