# 第六刀：C512 驻留与并行度账，四个逐位候选均未稳定过门槛

**决定：本轮不合生产、不装机、不发包。** 四候选都通过EXACT/AE七用例，900整网没有稳定≥0.5%的组合证据；按任务单“不到门槛交清账再停”交付。剑星两架构的C512模块及第五刀c64-wave2均与实验启动时哈希相同，见installed-identity.json。没有新安装，因而没有新增游戏备份。

基线是09-27 23:06第五刀实装（c64-wave2 gfx1201 f60eaee8），ViT stream=3、PDL=1。实验根 `D:\DLSSNR-Lab\hip-backend\c512-round1`，模块从游戏现场复制，生产hip/与host未改。gfx1201实测，gfx1200只编译。

## 各核的工作量、驻留与时间

实际生产Run记录grid/threads；hipFuncGetAttribute查询VGPR、LDS、private，hipModuleOccupancyMaxActiveBlocksPerMultiprocessor查询驻留上限。驱动报告32 MP（WGP）、wave32、2048线程/MP、64KiB LDS/MP，不能把64 CU当成此API的MP单位。以下VGPR是运行时查询/metadata数，所有核private=0。

900的C512处理token为1792/2240（6/7层），即28/35个8×8窗口；1080为2560，即40窗口。旧“104/135窗口”不能用于当前C512；104是当前900的C256 attention组数。C512 attention本来已按16头拆组，并非仅28/35组。

时间是整网内重复派发的**边际成本**：每个目标额外重复两次，同批ABBA差除以2；每槽20预热+160计时。六个主核各三轮，shift/pool等各两轮。两档主账各75次、边界账各35次原始FP32全幅校验，全部逐位。复制核改变缓存复用和功耗，不把各行相加当成准确整帧分解，也不把静态容量当作实测动态占用率。

## 按三个方向做的候选

新宏默认0，全部位于实验生成器；没有split-K、没有更改激活/归一化/求和顺序、没有新MODE段。初始默认关Z的两模块×双架构，与现场基线的.text/.rodata/.note全部相同，见default-code-identity.txt。

| 候选 | 改动 | 每wave普通向量 / VMEM / WMMA | VGPR / LDS / API组每MP |
|---|---|---|---|
| R | mix的两个独立结果共用RTZ和FP8打包，保留clamp与零规范化 | 1871→1657 / 320不变 / 256不变 | 96→97 / 0 / **64→56** |
| Q | QKV用现有q8_fused_round替代q8(F(...)) | 1117→939 / 198不变 / 256不变 | 155 / 5456 / 12，均不变 |
| N | mix输出32token×64通道改32×32，grid翻倍；每个输出仍完整顺序累加K512 | 单wave1509 / 224 / 128；**两wave**等价旧一wave，即3018 / 448 / 256 | 62 / 0 / 64 |
| L | QKV原值归一化后，输出复用raw头1024B；先把系数取到寄存器 | 1117→1115 / 198不变 / 256不变；DS174→148 | **155→151 / 5456→4420 / 12→14** |

L初版直接别名使编译器在每次字节写后重读系数（DS174→230、WAIT574→768），在GPU测试前改为先取inv0/inv1；最终正式候选为C512_QKV_LDS_ALIAS=2。raw[0..1039]旧值在串行归一化后已死，系数留在raw[1040..1071]；输出仅占头1024字节，地址不重叠，现有同步仍分隔生命周期。增加的转换/读取没有被漏算。

N使用独立具名导出和实验host benchmark-n.exe，按modules-N目录选择该导出并将grid翻倍。A组同一host走旧导出，故计时比较只改变切分；生产host未改。它每两个wave多读一份A，增大并行度并不免费。

ISA按实际CFG自然循环计数：mix K16循环32次，QKV主循环8次、尾循环2次；WMMA用独立公式核对256（N为128）。互斥条件尾部按上界，WAIT是条数，不是周期。脚本isa.py、isa-weighted.json包含L初版与最终版，原汇编hash见isa-hashes.json。

## 整网结果与正确性

完整NativeGameFrame/D3D12↔HIP回放，两档各两批ABBA，每槽1000帧、去前200；计时只读首尾。下表负数表示更快。每候选另做EXACT/AE各7×12帧，**共672候选帧逐帧相同**（连基线1344帧hash）；各候选AE均43复用+41刷新，336组决策的reuse/age/reason/relative/local/image逐字段相同。没有把计时所有帧冒称逐位验证。

| 候选 | 900两批 Δms（%） | 1080两批 Δms（%） | EXACT/AE候选帧 |
|---|---|---|---|
| L | -0.0105 (-0.11%) / -0.0079 (-0.08%) | -0.0132 (-0.10%) / +0.0198 (+0.16%) | 84 / 84 |
| N | +0.0230 (+0.25%) / -0.0015 (-0.02%) | +0.0363 (+0.29%) / +0.0458 (+0.36%) | 84 / 84 |
| Q | +0.0062 (+0.07%) / -0.0068 (-0.07%) | -0.0083 (-0.07%) / -0.0144 (-0.11%) | 84 / 84 |
| R | -0.0701 (-0.76%) / -0.0197 (-0.21%) | -0.0086 (-0.07%) / -0.0100 (-0.08%) | 84 / 84 |

R两批合并约0.48%，而第二批只0.21%，不能拿首批0.76%单独过线。Q是噪声级；N在1080两批都慢；L的900约0.1%，1080一正一负。没有成熟候选可合配方，所以“合配方后的整网ms”不适用；各批A/B绝对ms完整列在summary.json/measurements.csv。

**本轮的瓶颈判断：**

- mix既有M32已在复用权重，N把更多工作组交给GPU却增加重复A读取和普通指令，净收益没有出现；不支持继续仅按“总wave不够”拆组。
- R省214条普通向量，却增加一个VGPR并跨过API驻留台阶；小收益波动，资源代价必须同时记账。Q省178条但几乎不省时间，量化尾部不是这轮可直接兑现的大头。
- QKV是900最值得关注的核，但L确实提高容量、减少DS仍只省约0.008～0.010ms整网，不能把低驻留上限当作现成奖金。900倒挂的具体原因尚未闭环。
- 剩余重点更偏主循环供数、归一化/调度组织以及跨核数据生产者，而不是继续复刻这几种尾部小刀。没有DRAM硬件计数器证据，不宣称“纯显存带宽打满”；也不宣称C512已到极限。要继续需要改变切口，不能重跑N/Q/L或旧half出口、现场零扫描、一头一wave/PDL叠加。

## ACO怎么安排并行度

读取本机~/work/aco-isa实际SPV manifest与对应host，不只看shader默认宏：ffwd_wgw=4、ffwd_fm2_min=2560、gemm_proj_mt=32、gemm_proj_nt=128。源码SHA在aco-source-hashes.json。

- ffwd3每wave负责64通道组，4wave/组；小几何每wave16token，达到2560阈值才32token。按相同填充M归一化，900为224/280组（896/1120wave），2560token宽版160组（640wave）。**其实际M来自有效tile域，不等于我们的padding域**，这是尺度对照，不是假设备跑出来的调用统计。
- 它把mix→expand→contract融合，片段留寄存器，减少中间搬运；不是普遍把组数做得越多越好。数学/量化不同，本轮没有照抄。
- gemmproj实际tile32×128，4wave各算32×32：同M、N512时224/280/320组；我们16×64单wave组896/1120/1280。总wave相同、分组形态不同。
- C512 attention的host按窗口XY×头Z=16派发，我们生产attention也按头拆；这并非尚未采用的新办法。

## 剑星测900档

最直接：**1600×900窗口+FSR原生AA**，NETWORK_HEIGHT=auto（或900）；保持同一中画质与机位，F8切EXACT、读黄字小数。2560×1440+FSR质量档通常render=1707×961，两轴在1600×900的110%内，auto也选900。前者方便固定网络几何，后者对应常见2K使用场景。贴60时换主菜单或较重场景，不能拿封顶读数判断0.5%收益。本轮没有改动这些游戏选项。
