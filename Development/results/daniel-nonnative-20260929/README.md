# Daniel 非原生 1080P 闪烁 / 变糊：静态推断（2026-09-29）

网友群反馈："Daniel 从 0.4.3 起，不用原生 1080P 就闪烁、变糊。"本轮只做静态分析（0.4.0 / 0.5.0 / 0.5.1 的 `mod.dll` 字符串 + 9070 剑星目录里他 0.4.0/0.5.0 的会话日志），没有运行安装器、没有装进游戏。0.4.2/0.4.3 无二进制，只能从 0.4.0→0.5.x 的差异推断。

## 他的非 1080 路径（有日志/字符串为证）

- **网络直接跑在渲染分辨率上，任意尺寸**：0.4.0 剑星 2K 质量档日志 `pre-upscale mode: the network runs on the 1708x964 render-resolution colour (render size 1707x961)`，再裁到 1707×961；没有"缩到固定档位"这一步。
- **工作尺寸换了规则**：0.5.x 新增 `DLSSNR_EXTENT` / `DLSSNR_EXTENT_NO_W64` / `DLSSNR_PAD128`（0.4.0 字符串里没有），默认按他所谓"NVIDIA 原生工作尺寸"（ceil64，1080→1088），128 对齐改为回退。他自己的报错字符串承认有些尺寸走不通：`frame %dx%d on extent %dx%d: level %d would be %dx%d, and NVIDIA's single-tile mode for that is not ported`；另一条说旧的持久化链 "hung in the 128-padded baseline"，说明 0.4.0 时代的基线是 PAD128。
- **时序历史默认关**：日志每行 `history off`（`PreHistory=0`），他的说明原话："FSR's accumulator then provides the temporal filtering"。
- 对照 NVIDIA 原版（我们 09-28 查过）：1080 实际处理 1920×1152，对齐步长按层下采样次数取 2^count；post 位移 (-4,-4)。Daniel 1080 是 1088、位移 0。

## 最可能的原因（按证据强弱）

1. **中：0.4.x 把工作尺寸从 PAD128 换成 ceil64 "原生 extent"**，时间点与"0.4.3 起"吻合（0.4.3 自报 reference +20%，正符合少算补齐像素）。1080 时 1088 离原版 1152 不远，看不出问题；其它尺寸（1707×961、1600×900、1440p 等）会得到原版从没跑过的逐层尺寸与窗口切分（边缘半窗、ViT token 网格变形），有的尺寸他自己标注"未移植"。网络对这些几何是分布外输入，最可能表现为画质不稳和变软。
2. **中：预超分 + 无历史，在"放大模式"下被 FSR 放大成闪烁/发糊**。网络每帧只看当前抖动（jitter）后的低分辨率帧，残差随抖动逐帧变；原生 AA 时 FSR 只做抗锯齿，影响小；放大 1.5～3 倍时 FSR 要靠多帧子像素一致性重建细节，逐帧变化的残差会被当成噪声，结果是闪烁或被拒绝后发糊。这条不是 0.4.3 才有（0.4.0 已是 history off），但会放大第 1 条。
3. **弱：fast 档近似算术**（0.4.2 起默认 fast）在非 1080 尺寸下误差更易显形——无直接证据。

## 我们有没有同类问题

- **几何：基本没有他那种风险**。我们只在固定几何上跑网络：1080 档 = 原版合同 1920×1152 + (-4,-4)；非 1080 输入按 0.31 规则缩进/放入 720/900/1080 档（`native_network_geometry.h` `ForInput`，两轴都不超过某档 110% 就往下缩进），>1080 由 `DLSS5_FIT_LARGE` 降到 1080 档再按亮度比调制原图。**但 900/720 是我们自定的几何**（900 = 1600×960 处理），不是原版合同，属于同一类"原版没跑过的尺寸"——只是固定一种、有逐位回归，没有随窗口任意变化。
- **时序：同样无历史**。我们预超分路线也是每帧重置历史（`native_pre_upscale.h` 日志 `history_reset=1`，注释 "the network never samples motion/history in this prototype"），第 2 条的风险我们同样存在，只是没人报过。AE 复用（`DLSS5_VIT_ADAPTIVE`，常规包默认开）在运动时会刷新，但静止↔运动切换处也值得看一眼。
- 缩放本身：非 1080 输入经双线性缩到档位再回写，本身会略软；FIT 路径用亮度比调制原图，保住原图细节。
