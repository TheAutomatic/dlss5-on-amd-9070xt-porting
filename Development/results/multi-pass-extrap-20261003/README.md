# multi-pass-extrap-20261003：叠层 3 遍能不能用一阶外推 x + k·d 代替（纯离线）

## 导出口径（务必先看）
- 工具：叠层那次的 harness `benchmark-M.exe`（DLSS5_MULTI_PASS 分支），flat-M 模块，flags 与 `multi-pass-20261003` regression.ps1 一致（12 帧，adaptive 0），只取第 11 帧。脚本 `scripts/export.ps1`（9070 上跑，GPU 锁内），`scripts/run.sh`（等锁＋15 秒看门狗），`scripts/analyze.py`。帧哈希见 `hashes.txt`。
- **导出的不是网络输入张量，是 harness 最终输出（1296x720 RGBA16F，线性，解码器之后）**。没改代码拿不到网络分辨率的输入/输出张量（解码器的 Proxy/Neural 调试视图只有 RE9 runtime 接口能开）。所以：
  - x = `DLSS5_STRENGTH=0,0` 跑 1 遍：解码器原样返回游戏颜色（即"网络什么都没做"的整帧，与 y 同分辨率、同编码）。
  - y1/y2/y3 = `DLSS5_MULTI_PASS=1/2/3`，STRENGTH 1,1。
  - 四者都在同一空间（输出分辨率、线性、paper-white 归一），d = y1 − x 有意义。但解码器做了亮度比修正（原图/proxy 亮度比乘回）和 OKLab 换色，所以这里的"线性"是最终画面上的线性，不等于网络工作编码里的线性。
- 主空间 = 把线性结果 clamp[0,1] 后做 sRGB 编码（网络工作编码是 sRGB 类），副空间 = 线性 clamp[0,1]。PSNR 峰值 1，全分辨率 1296x720，无损 f16。
- 另加一组产品现成的做法：1 遍 + `DLSS5_STRENGTH=k,k`（解码器自己在 lerp 里外推，k=2/2.5/3）。
- 场景：900-static、1080-static、1080-motion、1080-history（history 有时序历史）。

## PSNR（dB，sRGB 编码空间；完整两空间数字在 `psnr.txt`）
| 场景 | y1→y3（不做） | y2→y3 | x+2d→y3 | x+2.5d→y3 | k*（拟 y3） | STRENGTH 2→y3 | x+1.5d→y2 | y1→y2 | k*（拟 y2） |
|---|---|---|---|---|---|---|---|---|---|
| 900-static | 26.51 | 31.23 | 28.98 | 28.98 | 1.45 | 26.85 | 33.56 | 30.73 | 1.35 |
| 1080-static | 27.36 | 33.70 | **30.40** | 30.10 | 1.55 | 27.26 | 33.86 | 30.73 | 1.41 |
| 1080-motion | 27.42 | 33.61 | **30.43** | 30.05 | 1.58 | 27.24 | 34.49 | 31.35 | 1.40 |
| 1080-history | 28.39 | 34.85 | **31.13** | 30.17 | 1.68 | 27.12 | 35.06 | 32.22 | 1.45 |

线性空间同样的顺序，数字高 7～10 dB：y1→y3 34.4～34.7（和上次 README 的"3 遍对 1 遍 34 dB"对得上），最好外推 39.2～40.6，y2→y3 40.6～41.8。
（k* 是不带 clamp 的最小二乘；带 clamp 后 k*≈1.5 的分数反而略低于 k=2，以 k 栅格为准。）

二阶：y3 ≈ y2 + k·(y2 − y1)，k* = 0.34～0.44（sRGB），PSNR 32.3～37.0。增量逐遍**收缩**：|y2−y1|/|d| ≈ 0.64～0.76，|y3−y2|/|y2−y1| ≈ 0.71～0.94。所以 3 遍 ≈ x + (1 + 0.68 + 0.5)·d ≈ x + 2.2d 只是方向近似，方向本身在每遍也会转。

分桶（拟 y3，sRGB）：
- 按 x 亮度三分：暗部/中间调外推 ≈ 不做或更差（中间调 36.7–37.5 vs 不做 37.4–38.7），**收益全部在亮部**（23.6–26.7 vs 21.9–24.0，+1.6～2.7 dB），亮部最优 k≈1.5–1.7，中间调 k≈1.0（即多跑的那两遍在中间调里不是沿 d 走）。
- 按频带（高斯 σ=2 拆）：低频外推 +2.1～3.4 dB（低频 k*≈1.5–1.7）；高频只 +0.3～0.5 dB（高频 k*≈1.0–1.35）。y3 的高频能量比 y1 多约 10%，外推只补上不到三分之一。
→ **外推放大的是对比度/亮部色调（低频），几乎放大不出纹理**；3 遍新增的高频细节不在 1 遍增量的方向上。

## 判断
- 一阶外推只能替代"多跑两遍"的一部分：按 MSE 算，x+2d 把 y1→y3 的差距消掉约 43%（900）～50%（1080），线性空间约 70%；分数始终不到 2 遍本身（y2→y3 比外推高 2.3～3.7 dB）。也就是说**外推的效果介于 1 遍和 2 遍之间，比 2 遍差**。
- 对 y2 而言外推更接近（x+1.5d 比 y1 高 ~2.9 dB，但距 y2 仍只有 33.6～35.1 dB），同样是低频成分。
- 解码器现成的 `DLSS5_STRENGTH=k,k` 不是这件事的替代品：k=2 对 y3 只有 26.9～27.3 dB，跟什么都不做（y1）持平，k 越大越差。它的 lerp 是在亮度比/OKLab 里做的，与多遍的走向不同。
- 能做的最多是个"便宜的对比度加强"选项（零成本，对比度/亮部像 2～3 遍），纹理那部分得真跑网络。数字不够撑"用外推替代叠层"。
- 局限：只看了 menu 截帧一张图（四种设置），x/y 是解码后整帧而不是网络张量；在网络工作编码里直接外推、再过解码器，结果可能略好，这次没测（需要改代码导出）。
