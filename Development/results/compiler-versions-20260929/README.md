## LLVM22的失败范围

- EXACT和AE各自：900静态、900运动、720运动、900历史四组各12帧不同，共96帧；1080静态/运动/历史两种模式共72帧同golden。
- 全部候选/配对基线都有限，没有NaN/Inf。AE40行字段变化，复用22次（基线44次）；不能只比较reuse开关而漏掉分数。
- 900静态的基线12帧只有1个hash，候选12帧有12个不同hash；这不是简单的±0规范化差异。
- 两个保存的RGBA16F样本：900静态frame0有2,678,614/3,732,480个half值数值不同，最大绝对差0.468262、RMSE0.042658；720运动frame11最大差0.307861、RMSE0.033611。这些是回放输出全部RGBA元素的统计，不包装成游戏画质/PSNR。

完整失败列表在[validation-L22.json](validation-L22.json)，AE逐字段在[adaptive-L22.json](adaptive-L22.json)，样本hash/量化在[llvm22-diff-samples.json](llvm22-diff-samples.json)。原始CSV与hash在 `replay-L22.zip`。本轮不定位编译器pass或内核根因；900/720使用的C256分体路径可作为以后切口，但没有证明是它或PDL导致。没有为了计时放宽数值门，也没有补算“只测通过的1080”。
