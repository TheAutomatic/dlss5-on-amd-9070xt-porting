# 尾部（decoder/head）与 C32 差距逐项拆账（2026-10-01）：尾部一刀逐位但不快，不收；C32 余差基本是数值取舍

**结论先行**：
- **尾部差距大部分是分族口径造成的，不是尾部慢**。差距表里"其他"一栏，我们的 54.8µs 由两个 decoder 核组成：块 39 Up（ViT→C512，`decoder_project2x_h16w` 19.7µs）和块 48 Up（C512→C256，`decoder_project2x_h16w_byteout` 35.1µs）。他的 15.5µs 由 DecInputUpsample（gemmvqkvs 6.5 + decups 2.7）和 FinalHead（gemmnores 6.3）组成，他的块 48 上采样折在 `fswinpup256` 里，被算进了 C256 那一栏。真正同口径的只有块 39：**19.7 对 9.2µs，差约 10µs**。
- 尾部候选 `HIP_DEC_NT`（每个 wave 算 NT 个输出列块，A 片段只读一次、只转换一次，逐位）：NT=4 三轮都变慢，NT=2 有一轮 900 变慢（+0.0014），**都不收**，宏默认 0。
- C32 的 +225µs 拆开以后（§2），prefix（+78，另有池化 18）和 post（+64）占大头，性质是数值取舍（f32 激活/归一化快路径）。组织方式上能逐位做的件，前面各轮都已经收了或者记了负账，**这轮没有新的组织方式候选**。

## 1. 尾部

| 我们（900） | µs | 他 | µs | 对应关系 |
|---|---:|---|---:|---|
| 块 39 `decoder_project2x_h16w`（1024→512，400 token，800 WG × 1 wave） | 19.7 | DecInputUpsample gemmvqkvs + decups | 9.2 | 同一件事 |
| 块 48 `decoder_project2x_h16w_byteout`（512→256，1500 token，1504 WG） | 35.1 | 折在 fswinpup256（UPS 层）里 | —（算在 C256 的 431.5） | 口径不同 |
| — | — | FinalHead gemmnores | 6.3 | 我们放在 C512 族 |

我们的组织方式：一个 wave 算 16 token × 16 列，A（f32→f16）被同一 token 行的 32（或 16）个 wave 各读、各转换一遍。
- 候选：同一个 wave 算 NT 个列块，A 只读、只转换一次，喂给 NT 个 WMMA。每个累加器看到的 k 顺序（含 4 段 parts 拆分）和尾处理都和原来一样。新导出 `decoder_project2x_h16w_n{2,4,8}` / `_byteout_n*`，宿主按导出挑最宽的。
- 19 组 SAME（NT=4、NT=2 各一次）。计时：

| | 900 三轮 | 1080 三轮 | 合并 avg / p99 |
|---|---|---|---|
| NT=4 | +0.022 / +0.030 / +0.015 | +0.011 / +0.009 / −0.002 | 900 7.4214→7.4437 / 7.664→7.670；1080 10.1604→10.1662 |
| NT=2 | **+0.001** / −0.018 / −0.007 | −0.015 / −0.023 / −0.005 | 900 7.4206→7.4128 / 7.688→7.637；1080 10.1495→10.1351 / 10.455→10.446 |

- 读法：wave 数减到 1/NT（块 39 从 800 降到 200/400），并行度下降的损失抵掉了少读 A 的收益。这两个核的耗时不在 A 上，大概率在尾处理：每个 lane 管一列、8 个 token 各 2×2 上采样散写，还有 skip f32 读。要赚得换成"LDS 转置后宽写"，属于 tail-vec 那一类改法；但 tail-vec 只做过 C32 finish，没做过 decoder。
- **不收**：NT=2 的 900 第 1 轮 +0.0014ms 按规则算变慢。宏默认 0，源码留在本次提交（只加导出，现有函数不变），配方不改。

## 3. 建议

- 尾部下一刀（如果要做）：decoder 尾处理改成 LDS 转置后按行宽写（块 48 输出是字节，每个 lane 现在逐字节散写 32 次），同时 skip 按行读。预期只在块 48（35µs）上兑现，块 39 是 f32 行写，已经较宽。
- C32 不再在"组织方式"上找刀；剩下的差距要动数值，归 C 段（需 Zero 拍板）。

## 4. 最后一刀：decoder 尾处理 LDS 转置 + 行宽读写（`HIP_DEC_WIDE`），逐位，但 900 有一轮变慢，不收

块 39、块 48 用同一个 tile 和同一串 WMMA，只改尾处理：H(total) 先写进 LDS（16×17 float）。之后每个 lane 负责一个输出像素的连续 16 个通道：skip 用 4 条 b128 读，scale 用 4 条 b128 读，每个元素照原式计算 `H(t+F(skip)*scale)`、F / fp8_add0，字节输出一次 b128 写，f32 输出 4 条 b128 写。新导出 `decoder_project2x_h16w_w` / `_byteout_w`，宿主优先选它。19 组 SAME。
