## 2. 功耗与频率（逐族）

方法：现装逐位档（剑星 gfx1201 模块、宿主 benchmark-S，与现装 add-on 同源），每个族 `DUP_COUNT=8` 让它占满一帧，ADL 200ms 遥测（只取 GFX 活动 ≥90%、丢前四分之一），两轮、各 1000 帧（`powerfam.ps1`，分析 `powan.py`，表 `power-table.md`，span `spans.txt`）。第一批跑到一半 Zero 进了游戏，整批作废后重测；重测时有 `guard.sh` 每 15 秒查一次游戏进程，中途触发过一次中止，重跑后的数据完整。

- **板功耗在每个配置下都钉在 322～328W**（功耗墙），变的只是时钟：基线 900 档 2784MHz，1080 档 2710MHz。
- 用功耗墙模型（1/f = Σ 时间占比 × 每周期能耗），从"基线 + 占满"两次运行反解出每族每周期能耗相对全帧均值的倍数（表里的 eps 列）。**最耗电的是 C64/C128 wave2（1.08～1.10）、C32（1.04～1.06）**；ViT expand 1.09～1.16，但它占比小、读数噪。**C512 各核都低于均值**：QKV+attention 0.89～0.93、FFN 0.80～0.95、attention 投影 0.90～0.92。ViT attention/stream 大致在均值附近。
- 估算（上界，按"时间 ∝ 1/时钟"算）：某族每周期能耗降 10%，全网时钟上升幅度约等于 10% × 该族的能耗占比。C32 能耗占比 0.21～0.23 → 时钟 +2.1～2.4%，约 −0.14 / −0.23ms；C128 → 约 −0.08 / −0.11ms；C64 → 约 −0.06 / −0.09ms；C512 单核都只有 −0.04～−0.06ms。
- 逐位能否降能耗：这些族已经是全帧最耗电的，但相对均值只高 5～10%。09-24 的功耗账本找出的大头"全局窄写"，已经在 mhfast 整行写那刀里收了。C32 多出来的能耗来自逐位保留的 VALU 链（Hrtz/RTZ），属于数值取舍，逐位动不了。C64/C128 我没有找到便宜、能逐位的去冗余件，要让某族能耗降 10% 以上，现在没有现成的办法。**没有出候选，只交报告。**

## 3. C512 attention 投影（还差约 11µs/块）

诊断宏 `C512_PROJ_ABLATE`（默认 0，开了输出是错的；宏 0 时编出的模块与现装逐条相同）：bit1 残差初值改 0，bit2 去掉 K 循环，bit4 不写出。另做 DUP×2 对照。三轮、各 600 帧，每块 µs = Δspan/13（`projab.ps1`）：

| 对照 | 900 | 1152 行 |
|---|---:|---:|
| DUP×2（链里多跑一遍） | +14.5 | +22.8 |
| 去残差读（a1） | −2.5 | −5.1 |
| 去 K 循环（a2） | −4.5 | −6.4 |
| 不写出（a4） | −1.4 | −0.5 |
| 去 K 循环 + 不写出（a6） | −5.2 | −8.3 |
| 核内全空（a7，只保留派发） | **−5.6** | **−9.3** |

- 把核体完全掏空也只省 5.6 / 9.3µs/块。事件地图记的是 18.8 / 25.0，DUP 记的是 14.5 / 22.8，两种方法都把"和邻居重叠被打掉"的部分算成了成本。**这个核在链里真正的本体成本已经不大于 mochizuki 的 Proj（7.8 / 9.7）**，剩下的差在派发和衔接（启动加依赖等待），不在核体里。
- f32 残差往返值 2.5～5µs（主要是读），写出几乎不花时间。即使残差读全免，最多也就这么多；而 B8 字节残差（`C512_PROJ_FB8`）已经实测持平，和这个上限吻合。
- 功耗角度：第 2 项里这个核的每周期能耗是均值的 0.90～0.92，不耗电，功耗这条路也不通。
- 结论：核体内已经没有能逐位追的东西。要追这段差，只能减少派发次数（把投影并进 QKV-attention，即 B.2 那条"块内就绪队列"），而跨块的同一机制 P 已经因为功耗墙被否了。**没有新角度，交账，不做候选。**
