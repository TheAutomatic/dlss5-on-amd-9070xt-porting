## 2. 归类
- **组织方式**：池化单独派发（900 29+19µs）；每段 5～7 个派发，他 1 个持久化派发（空档约 2µs/派发 × 18 个 ≈ 40µs）；Up 首块尾处理（本刀）。持久化和下采样融合已经交过负账。
- **数值取舍**：中间块本体。他 `NR_ACC_F16` f16 累加、蝶形归一化，我们 f32 按 NVIDIA 顺序。逐位追不了，这部分是中间体差的主体（真实量待定，见上面的注意）。
- **数据格式**：C64 链尾 f32 → C32Up（+22，`CW_UP_LOW_BYTES` 已负账）；skip 读 f16（2B），他全程 e4m3。Up 只要 F(skip)，但池化需要完整的 f16，所以不能直接改成字节，除非链尾双写。
- **派发空档**：已含在 step 里，约 2µs/派发。

## 3. 候选 `W2_UP_VEC`（`hip/wave_owned_mh.inc`，源码默认 0，需要 `HIP_ISA_HALF`；c64-wave2 配方写 1）
- H 就是 `v_cvt_f16_f32`→`v_cvt_f32_f16` 两条 ISA，shuffle 只是纯搬运。所以先在源 lane 上转 f16，两个打包进一个 32 位字 bpermute，到目标 lane 再 cvt 回来，和 H(shuffle(t)) 逐位相同，NaN 也一样。bpermute 从 64 次降到 32 次。
- skip 每个（qt, ci）一次 16B 向量读（f16），原来是 8 次 u16。upw 的 16 个值提到 qt 循环外，原来每个 qt 都要 8 次 b32。尾循环全展开。merge 表达式和字节选择照原样写。
- 只改 8 个 Up 函数，其余函数逐条相同。prod 重编的 `.text` 等于现装 38FEEB70；final 的 `.text` 等于实测 UV。VGPR 138→140，private 0。
- 逐位：基准 = 剑星现装 31 模块（c64-wave2 38FEEB70）+ main HEAD 宿主（base、P 同源）。**19 组 SAME**。

### 6.1 链中间块多出的 12～15µs 是真的（不是事件伪影）
办法：不打事件。在生产 flags 上加 `DLSS5_HIP_DUP_PREFIX=<核名>$` + `DUP_COUNT=2`，把这个核的每个实例紧跟着再跑一遍（纯函数，输出不变）。span 增量除以实例数，就是在生产链里多跑一个实例的代价。宿主 evprof 不开 profile，模块 = 现装（含 UV），300 帧弃 60 取中位，三轮。脚本 `dup.ps1`，原始数据 `dup-spans.txt`。

| 核（实例数） | 900 三轮（µs/实例） | 均值 | 事件估计 | jobbench 单核 |
|---|---|---:|---:|---:|
| c128_wave2_bi_bo（9） | 66.0 / 71.6 / 69.1 | **68.9** | 73.9 | 58.6 |
| c64_wave2_bi_bo（4） | 90.8 / 95.5 / 92.3 | **92.8** | 94.6 | 82 |
| 1080 c128 bi_bo | 110.0 / 110.3 / 110.4 | **110.3** | 102.3 | — |
| 1080 c64 bi_bo | 129.5 / 129.2 / 132.8 | **130.5** | 131.3 | — |

单实例的核（Up 首块、链尾 bi/ho）每轮差 ±15～40µs，只能看量级，不列。**结论**：链内中间块确实是 C128 约 69、C64 约 93µs（900），和事件估计一致。jobbench 偏低，最可能的原因是单核跑时时钟更高（clock-ledger：单测 3.1GHz，整网 2.74～2.79GHz；58.6×3.1/2.77≈66）。所以"中间体差"是真的：C128 中间块每层约 69，他每层均摊 ≤60（均摊里还含 DS/UPS），C128 两段 9 个中间块在 900 下大约是 +100µs 的量级。**这是 C64/C128 剩下的最大一笔**，归类是数值取舍（他用 f16 累加）加块本体的组织方式，下一步应该往块本体拆（FFN / QKV / attention 各占多少）。

## 7. C128 中间块拆段（c128-phase，同日）+ `W2_QKV_FUSE`（已收并装机）

### 7.1 段成本：段重放法
探针宏 `W2_PHASE_REP=<bit>`（只做计时，不进配方）：只让 `c128_wave2_bi_bo` 的某一段在核内跑两遍。每段都是幂等的（重写同一块 LDS 或同一个输出），所以输出不变。span 增量除以 9 个实例，就是这一段在生产链里的成本。重放循环只在目标核里生成，模块里其余函数逐条相同。脚本 `phase.ps1`，原始数据 `phase-spans.txt`，三轮。

| 段（bit） | 900 µs | 1080 µs |
|---|---:|---:|
| 输入搬进 LDS（32） | 2.5 | 4.1 |
| FFN 扩展→激活→收缩（1） | 23.7 | 34.4 |
| FFN 跨头混合 + 残差（2） | 6.9 | 11.3 |
| **QKV 投影 + 归一化（4）** | **27.7** | **40.3** |
| attention（8） | 9.4 | 14.0 |
| 输出投影 + 写回（16） | 9.0 | 12.6 |
| 各段之和 / 整核 DUP | 79.2 / 73.5 | 116.7 / 111.6 |

各段之和略大于整核，差的是段之间的重叠。**QKV 是最大的一段**：每个 wave 只有 192 次 WMMA，比 FFN 的 320 次少，却更贵。原因是组织方式：原来按 part 在外、qt 在内，A 片段要从 LDS 读三遍，每个 part 的累加链串行。他的 fswin（以及我们 C512 已收的 FUSEQKV）是在一个 kt 循环里同时算 Q/K/V。归类：**组织方式，可以逐位做**。FFN 那两段、attention、输出投影和他的差别，主要在 f16 累加（数值取舍，只记账）。他的持久化核拆不出单段计时，逐段对比只能对照源码组织方式。
