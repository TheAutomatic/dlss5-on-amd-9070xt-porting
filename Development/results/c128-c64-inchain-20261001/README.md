## 2. 归类
- **组织方式**：池化单独派发（900 29+19µs）；每段 5～7 个派发，他 1 个持久化派发（空档约 2µs/派发 × 18 个 ≈ 40µs）；Up 首块尾处理（本刀）。持久化和下采样融合已经交过负账。
- **数值取舍**：中间块本体。他 `NR_ACC_F16` f16 累加、蝶形归一化，我们 f32 按 NVIDIA 顺序。逐位追不了，这部分是中间体差的主体（真实量待定，见上面的注意）。
- **数据格式**：C64 链尾 f32 → C32Up（+22，`CW_UP_LOW_BYTES` 已负账）；skip 读 f16（2B），他全程 e4m3。Up 只要 F(skip)，但池化需要完整的 f16，所以不能直接改成字节，除非链尾双写。
- **派发空档**：已含在 step 里，约 2µs/派发。

## 3. 候选 `W2_UP_VEC`（`hip/wave_owned_mh.inc`，源码默认 0，需要 `HIP_ISA_HALF`；c64-wave2 配方写 1）
- H 就是 `v_cvt_f16_f32`→`v_cvt_f32_f16` 两条 ISA，shuffle 只是纯搬运。所以先在源 lane 上转 f16，两个打包进一个 32 位字 bpermute，到目标 lane 再 cvt 回来，和 H(shuffle(t)) 逐位相同，NaN 也一样。bpermute 从 64 次降到 32 次。
- skip 每个（qt, ci）一次 16B 向量读（f16），原来是 8 次 u16。upw 的 16 个值提到 qt 循环外，原来每个 qt 都要 8 次 b32。尾循环全展开。merge 表达式和字节选择照原样写。
- 只改 8 个 Up 函数，其余函数逐条相同。prod 重编的 `.text` 等于现装 38FEEB70；final 的 `.text` 等于实测 UV。VGPR 138→140，private 0。
- 逐位：基准 = 剑星现装 31 模块（c64-wave2 38FEEB70）+ main HEAD 宿主（base、P 同源）。**19 组 SAME**。
