## 方法
- 现装：剑星 31 个 gfx1201 模块直接拷自游戏目录（哈希见 `installed.txt`，add-on 7E19CC6B 同源），宿主 = origin/main 640493c9 + kernel-map-v3 的事件探针补丁；每派发记一对 hipEvent，输出 exec（开始→结束）和 **step（开始→下一派发开始，含空档）**，step 与他的"时间戳到时间戳"同义。flags 同 regression（PDL/WAVE_OWNED/SWIN_RUN=1/DIRECT_IO=3/MAKE_RESIDENT_EVERY=60），NativeGameFrame 回放 300 帧弃 60，逐派发取中位。
- **事件开销**：带探针的 span 是 13.99 / 16.81ms，不带是 7.01 / 9.74ms——每派发一对事件约 **42µs** 恒定开销（空核 sp_init/sp_recover 读 ~43µs 旁证）。按档求 f 使 Σ(step−f) = 无探针 span：f = 41.7（900）/ 42.6（1080）µs，表中每族 = Σ(step) − 派发数×f。这是均摊修正，逐核误差约 ±几 µs；族合计对齐 span 是强约束。
- 事件会把 PDL/any-order 链串行化——他那边每派发之间本来就有 barrier，同口径；我们的生产 span（无探针）已经含 PDL 重叠，所以修正后族合计略低估 PDL 族、略高估其它族，量级在空档（~2µs/派发）以内。
- 已知伪影：C64 链尾 `c64_wave2_bi`（接 C32 up 之前那个）两档都读成负值（结束事件排到开始前面），按前一个 `bi_bo` + 22µs（jobbench 的 bi−bi_bo 差）替补，已标 `artifact`。
- 他的数取自早上的 `pl{1,2}-*.log`（他的程序没变）；族归类沿用 `mochizuki-gap/fam.py`。

- 队列本体**每层已和他持平**（900 约 53 对 51～54µs）；init+recover 两个轻派发每段约 14µs。C256 900 的 +141 主要在链两端：编码块 15（ffn 60.8 + attn_bo 23.9）、块 22（ffn 37.1 + f32 出口 `c256_attn_wave` 34.9）、池化 19.0，解码块 49/55 各两核 ~83/58——他把这些都放在同一个持久化派发里。把两端并进队列（`SP_ENDS`）在今天的新基线上 1080 不赚（见 c256-gap），所以 C256 剩下的钱在"两端的核本体"，不在队列。
- 本体内部（每层 ffn/attn/发布/领票）事件拆不开；上表"拆成单核"一行是串行化的上界，不能直接当本体分项。
