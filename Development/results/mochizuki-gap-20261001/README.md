## 2. 前 3 大差距从哪来

1. **C512（900 +0.50ms，还是在我们少跑 3 块的情况下）**。每块：他 ffwd3 13.8 + FFN 投影 7.9 + attn 23 + 投影 7.6 = 52.3µs；我们 mix 14.5 + ffn 14.1 + 投影 8.9 + qkv_attention 46.5 + attention 投影 16.8 = 100.8µs。
   - attention：他和我们的工作组都是（窗口, 头），2 个 wave，网格一样（448/560）。**差在组织方式**：他 Q/K/V 在一个 k 循环里用 6 个累加器（`NR_APARTS=1, NR_AN=6`），X 片段只读一次；越界判断提到循环外（`NR_ATTN_EDGE`）。我们分三趟，每趟都重读 X，每步都做越界判断。→ 本轮已改（见 §3）。归一化他用 f16 蝶形，我们用 f32 串行对 NVIDIA 顺序，这一条属于**数值取舍**，不动。
   - FFN：他 `ffwd3_t.comp` 一个核做完 mix→expand→act→contract。权重当 A、激活当 B，这样累加器的布局正好就是下一级 B 的布局，**不用 LDS，也不用屏障**。我们拆成 mix（写 f32 到显存）+ ffn 两个核。归类：**组织方式**。这对应 B 段的 F，他的寄存器转置用法说明不一定要 50KB LDS。
   - 投影：他的残差和输出都是 e4m3（`NR_R_E4M3`）；我们的残差按 f32 读写（值其实是 F() 之后的 fp8 值，post=3 的 Hrtz 除外），流量是他的 4 倍。归类：**数据格式**，大部分逐位可行，要改宿主。
2. **派发空隙（900 约 +0.3ms）**。他 C64/C128/C256 每段只有 1 个持久化派发（down 和 up 各一个，`fswinpds*/fswinpup*`，下采样/上采样也折进去了）；C512 每块 4 个派发，我们 5 个。我们 C256 有持久化，C64/C128 没有（已交负账：持久化在这两段不赚）。归类：**组织方式**。
3. **C32（900 +0.23ms）**。结构一样，网格也一样：prefix 594 对 515，post 588 对 524，chain 约 120 对 108～117。C32 受 VALU 限制；他用 f32 激活/归一化快路径（`NR_ACT_F32`、`NR_QK_SCALE_FAST=5`、`NR_NORM_F32`），我们用对 NVIDIA 的精确序列。归类：**大部分是数值取舍**，小部分是编译器产物（他在源码里全展开），逐位的余地小。

ISA：他的 Windows 管线是 AMD 驱动里的 LLPC 编的，这次没有导出 ISA（RGA 用的编译器和驱动不是同一个）。第一刀靠源码结构对照就够了，逐条 ISA 对照留给下一刀（FFN）。

## 5. 第二刀 `C512_FFN_ONE`：C512 mix+FFN 合成一个核（已收下并装机）

- 做法：照 ffwd3 的组织。一个 wave 负责（64 通道组 g，32 个 token），网格和 mix m32 相同。mix 和 expand 都把 WMMA 操作数对调（权重当 A），累加器出来就是一个 lane 对应一个 token，正好是下一级的操作数布局。所以不用 LDS、不用屏障，也不再写 f32 mix 张量；contract 的 f32 副本本来就没人读，也不写了。
- 两段之间的量化：mix 出口 `F(c512_hq(acc))` 算完直接转 half 当 expand 的输入（旧路径是存成 f32 再读回来转 half，读写本身不改值）。expand→act→`byte_F` 也是逐字节照搬。**寄存器里逐位复现成立。**
- 新宏：模块宏 `C512_FFN_ONE`（`hip/c512_m32_deep.inc`，源码默认 0；c512-m32-deep 配方写 1，另加 `HIP_BYTE_F_ADD0 1`，和 deep_fast-packed 的 byte_F 口径对齐）。宿主 `HIP_C512_FFN_ONE`（默认 1，按导出存在与否回退，同 W16 的先例；旧模块走旧的两派发）。这是编译期开关，没有运行时 flag。
- 资源：VGPR 144，private 0，无 LDS。
- 逐位：19 组 SAME。另外，合入 swin 线 W2_UP_LOW_BYTES 之后的宿主 P3，在现装 Stellar 模块上对比"加新模块"和"不加"，也是 19 组 SAME。
